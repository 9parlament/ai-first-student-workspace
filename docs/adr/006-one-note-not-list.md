# ADR 006: одна заметка на пользователя, не список

**Статус:** предложено  
**Дата:** 2026-08-19

## Контекст

В takeaway уже есть каталог `items` (список Alpha/Beta/Gamma) и auth. Следующая фича — заметка. Развилка: **список заметок** vs **ровно одна заметка на пользователя**. Вторая развилка: гонять ли **delete** на prod вместе с остальным CRUD.

Список раздувает сценарии (пусто / много / порядок / пагинация) и провоцирует e2e на весь CRUD. Delete на витрине без OK портит демо-данные (`cfg-stands`).

## Решение

1. Продукт: **одна** заметка на пользователя. Нет списка, нет второй сущности «заметки во множественном числе».
2. Повторный create — ошибка или upsert (уточнит реализация); это правило **unit/integration**, не UI-грид.
3. «100% пирамиды» = каждый сценарий заметки на своём `@Layer`, не e2e на create+read+update+delete и не 100% JaCoCo.
4. Delete/drop на **prod** — только после явного OK человека и отдельного `@Tag`. Pipeline (`-Denv=ci`) и stage — можно: стенд пересоздаётся.

## Последствия

- Не проектировать `GET /notes` как коллекцию и не писать e2e «прокликать список».
- Контракт HTTP — ярус `api`; один браузерный happy path — `e2e`; разрушение на бою — не по умолчанию.
- Пока статус «предложено»: не считать delete-на-prod согласованным.
